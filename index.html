01CHATGPT / CODEX
开发助手 · 学习辅导 · 创作协作

ChatGPT / Codex
从一个想法，到可以试用的作品。

这份记录覆盖的任务比较广。我用它讨论需求、编写和修改代码、制作网页与素材，也会继续追问实现原理。较完整的过程通常是：先做一版，再根据试用结果不断调整。

A / 软件实践

拼豆应用与鸿蒙原型

拼豆项目从图片转图纸开始，逐步加入裁剪、MARD / Artkal 色卡匹配、颜色数量控制、用豆统计、逐格编辑、撤销重做与自动保存，还支持 PNG 和分页 A4 PDF 导出。

“生活回路”则围绕设备使用节奏，尝试目标、趋势、通知与页面联动；后续讨论中，重点从应用排行转向现实行动与温和提醒。

B / 学习与小工具

把概念变成可操作的示例

我用它解释 Python、编辑器、解释器、库和虚拟环境的区别，分析日期累计、整除与索引等基础问题，并制作带勾选、搜索和进度保存的学习路线网页。

还尝试过文件夹整理脚本、SVG 动画和《雾港电台》文字冒险游戏。游戏包含分支剧情、多结局、物品和状态系统，以及自动存档。

C / 视觉与表达

在反馈中细化效果

桌宠、角色头像和图标创作中，我会反馈人物特征、动作与画面问题，要求调整提示词或素材。桌宠有生成包与格式校验记录，但多轮效果仍未完全满意。

校园展示与简历排版中，AI 参与内容草拟、页面制作和格式调整；我提供已有经历、表达偏好和修改意见。游戏录屏方面只形成了剪辑构思，没有实际成片。

一个具体的迭代案例

图片能转成图纸，
还要检查比例是否正确。

最初的功能可以继续扩展，但实际试用暴露的问题同样重要。拼豆记录中的图片比例调整，体现了从“生成代码”到“检查使用效果”的过程。

  1. 提出目标将图片转换成可参考制作的拼豆图纸。
  2. 试用并反馈发现长宽比例问题，提出避免图像拉伸的要求。
  3. 继续修改AI 调整比例处理，后续还把图纸宽高上限从 160 格扩展到 240 格。
记录中的成果

拼豆 0.3.0 有正式签名 APK、四项单元测试和 Lint 检查记录；《雾港电台》验证过页面加载和主要界面。鸿蒙应用仍是原型，桌宠未确认最终满意并安装。

这类使用带给我的体会

需求表达、试用反馈与结果检查都需要继续参与。代码写出来以后，也值得追问 Kotlin、Compose、图像处理与导出流程为什么这样实现。

02WORKBUDDY
编程答疑 · 文件制作 · 环境排查

WorkBuddy
把一次答疑，整理成能反复使用的材料。

我使用 WorkBuddy 较多的场景是 Python 学习、代码反馈和文件制作。它能结合本地文件说明问题、生成练习网页，也参与过演示文稿、MCP skill 和电脑环境排查。

A / 编程学习

从语法解释到独立解题

围绕列表、map、random、格式化输出、位运算和对象比较等问题，用图解、示例与运行结果辅助理解。除了阅读代码，还增加了“给需求、自己组织代码”的练习。

产物包括 Python 练习 HTML、洛谷入门解题手册、print 专项练习、列表用法与拷贝速查，以及带注释的 Python 示例。

B / 展示制作

内容、版式与口播一起调整

历史案件主题《别笑你也过不了第二关》从方案到成品有八次改版，形成 24 页演示材料。AI 参与资料组织、分镜与文件生成，我对叙事逻辑和页面效果提出反馈。

班长竞选 PPT 也有初版、黑底改版与规范重制等阶段，涉及字体、间距、字号层级、配色与现场口播。

C / 工具与概念

学习如何把工具接起来

尝试制作麦当劳点单 skill，配置 MCP 连接并排查信任设置；尝试流程时因地点没有可配送门店而停止，没有完成订单。

还讨论过本地模型选型、MuJoCo 抓取入门，以及有界函数、复合函数和多模态模型等概念；部分调研与练习并未继续完成部署或后续阶段。

一个具体的学习案例

先指出问题，
再由我自己把代码改对。

作业二的反馈不仅给出“对或错”，还指出排序方向、随机数范围、下标和分支处理等问题。这个过程保留了自己的修改练习。

  1. 运行与定位对 14 道题逐题检查，记录通过、建议修改和必须修改的情况。
  2. 理解边界区分 randint 包含两端、range 不包含右端点，并检查索引与分支。

记录中的成果

形成多份交互式学习材料、代码示例与演示文稿。MuJoCo 后续里程碑、本地模型实际部署及显示刷新率问题，仍有未完成事项。

这类使用带给我的体会

读懂代码之后，还要练习拆解题意和处理边界。把一次答疑沉淀成速查页、例题和可重复使用的文档，有助于以后回看。

DSH
尝试更复杂的工具任务与信息整理。

在 DSH 中，我既探索过 Agent 的能力与插件，也尝试把已有工程迁移到鸿蒙、阅读多篇论文，以及制作系统化 Python 示例。记录里也明确保留了视觉能力与执行环境的限制。

A / FastCtx 扩展

为 Agent 增加文件工具

从“制作一个 FastCtx 模式”的需求出发，AI 阅读 preset 与 MCP 相关说明，制作用户级配置，并保留原有工具能力。

历史记录显示，模式被识别为健康，注册了 inspect_local_file、grep、glob 和 replace 四个工具，实际完成过文件读取；后续日志也记录到该模式的使用。

B / 学习与工程

从示例代码到鸿蒙工程

针对浮点精度与基础语法，生成了两份带大量逐行注释的 Python 学习文件；历史记录中有运行验证，也注明部分后续学习网页来自其他工具。

鸿蒙拼豆案例先读取现有 Android 工程与规格，再由 AI 使用 ArkTS 重写，随后根据我反馈的报错修正配置、类型和接口使用。不能据此确认鸿蒙装机或上架已完成。

C / 语言与创作

纠错、改写与提示词调整

英语写作中，DSH 参与词语解释、拼写和语法纠错，也对整篇文章进行了结构改写；这些文本并非全部独立写作成果。

头像创作中，DSH 主要提供和调整提示词，成图来自其他工具。当时视觉模型未配置或不支持读图，因此只能根据我的文字反馈讨论效果。

一个具体的研究辅助案例

五篇论文放在一起，
先理清各自解决什么问题。

围绕 LagMemo、UnitedVLN、VoLo 和两篇 3D Gaussian 相关论文，AI 辅助整理方法、贡献、实验与局限，再按我的要求给出通俗解释。

  1. 抽取材料将 PDF 转成文本，处理编码、空格缺失与表格数字粘连等问题。
  2. 分工整理记录中使用四个子代理并行整理部分论文，再与另一篇汇总成对照。
  3. 保留疑点对数字标注可信、存疑或推断，提醒回看原 PDF，而不是直接当成确认事实。
记录中的成果

有 FastCtx 用户级配置、Python 学习文件、鸿蒙工程修改和五篇论文综合概括。Claude Code 启动排障未收尾，鸿蒙装机也没有完成确认。

这类使用带给我的体会

工具能连接起来，不代表每项能力都具备；论文能被概括，也不等于数字与结论都准确。需要把工具限制、材料误差与待核实信息留下来。

04马维斯
英语资料 · 文档转换 · 内容校对

马维斯
把分散的学习资料整理得更清楚。

相比其他工具，马维斯这份记录的用途更集中：围绕英语视听说课程，完成教材格式转换、题型提取、听力原文整理与答案校对。这里主要展示资料处理过程，不将材料生成等同于学习或作业已完成。

A / 格式处理

从 PDF 到便于整理的文档

围绕《新一代（基础篇）视听说教程 2》的学习资料，使用 AI 将教材 PDF 转换成 Word 或 PPT，方便继续加工与整理。

需求不只是提取文字，还包括把结果写入实际文件，并检查产物是否存在。

B / 按题型组织

让题目、答案与原文对应起来

按单元整理 iExplore 1 的四选一听力题，将题干、选项、加粗答案及对应听力原文放在一起。

根据任务要求筛选题型，去掉不需要的判断正误、选词填空或勾选多选等内容，使文档结构保持一致。

C / 内容核对

对照图片继续修正细节

根据教材图片，调整选词填空文档的挖空位置与内容，并对整理出的题目和答案进行校对。

这里的答案整理与格式加工是 AI 辅助任务；记录没有确认后续提交、成绩或全部知识点的掌握情况。

一个具体的资料整理过程

不仅要“解析了”，
还要检查文件是否真的生成。

历史记录提到过“只解析、没有实际写入文件”的情况。后续需求因此更明确：整理结果必须落实为文件，并核实写入情况。

  1. 限定整理范围明确单元、题型、文档格式和需要保留的字段。
  2. 组织并校对把题干、选项、答案和听力原文关联整理，结合教材图片修正。
  3. 核实交付要求实际写入磁盘并检查文件，不能仅凭 AI 表示“已完成”。
记录中的成果

主要是视听说题目、原文与格式转换文档的整理记录，没有覆盖其他广泛用途；摘要没有提供可用于评价成绩提升的结果。

这类使用带给我的体会

材料整理也需要清楚的规格和校对步骤。筛选什么、如何对应、文件有没有生成，都应成为检查的一部分；有了资料以后，仍需要自己学习。

03 / HOW I WORK WITH AI

一次协作，通常不止一句提示词。

在应用开发、代码练习和演示制作中，多轮反馈是这些记录反复出现的共同过程。

01

说清楚问题

明确要解决什么、给谁使用，以及格式、时间或运行环境等约束。

02

让 AI 先做一版

获取代码、草稿、素材或结构方案，再查看是否符合原来的目标。

03

试用并指出问题

从图纸比例、程序报错、人物特征到发言逻辑，提供具体反馈。

04

修改，再检查

继续调整结果；把已验证的部分与尚未完成的部分分开记录。

04 / WHAT I LEARNED

能生成一个结果，
还要追问：为什么这样做，
它真的能用吗？

这些记录里，既有做出来的应用和文档，也有没跑通的配置、未满意的图片和仍待验证的原型。它们共同构成了我的 AI 使用经历。

01

理解原理，保留自己的练习

学习时曾主动关闭代码补全；遇到错误后追问原因，并在反馈后自行修改，而不是只收下一份答案。

02

把反馈说得具体

“不好用”可以继续拆成比例不对、数字不同步、层级不清楚。更准确的反馈，才有助于下一轮修改。

03

核对输出，也承认边界

论文数字需要回看原文；网页能打开不代表功能全部正确；素材格式通过，也不代表画面已经满意。

04

如实说明协作与成果

代码、文章和素材中都有 AI 的参与。完成草稿、做出原型、通过验证与正式发布，是不同阶段。
